## What memkernel does today (`main` at `3ba5c72`)
- Export writes `memkernel_ref`, `memkernel_sha256` and `memkernel_hash_scheme` on every draft page (`src/memkernel/wiki/sync.py:403-406`).
- Import reads only `corrects:` (`sync.py:843`), which supersedes the named memory when a curator corrects it. A page approved without `corrects:` becomes a new memory, and its source stays live beside it, so recall and the hook blocks can show both.
- Promoted chains collapse in the hook blocks (`src/memkernel/lifecycle.py`, `_distinct`) and are left out of promotion candidates (`src/memkernel/core/services.py:1558`). MCP `recall` collapses neither chain.

## Owner's decisions (2026-11-25)
- Hide the source; don't supersede it.
- Link only when the named memory is live, in the project scope, and its hash matches the page's `memkernel_sha256` under `memkernel_hash_scheme`.
- A page without `memkernel_ref` gets no link.
- `corrects` wins over `memkernel_ref`.
- The spec says whether a hidden source stays a promotion candidate, and whether wiki-studio's ADR-0002 should register `memkernel_ref`.
- Hook latency goes to Phase 4, not S5.
- Order: S5's spec PR, then #90's build, then S5's build.

## Out of scope
