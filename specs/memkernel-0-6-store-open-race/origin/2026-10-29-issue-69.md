# Origin note: #69, a new store's first open races (2026-10-29)

gosha70/memkernel#69 (posted 2026-10-29, after review) reports that in a project's first session the
`SessionStart` hook and memkernel's MCP server open the same new ChromaDB store at once, and the loser fails with
`chromadb.errors.InternalError: ... table collections already exists`. Evidence: four failed `SessionStart` hook
runs in the 0.5 measured run (`eval/lifecycle-suite/report-0.5.0.md` §4) and a reproduction with plain chromadb
1.5.9 (2 of 20 trials). It lists three options for the spec to decide: A, retry the open; B, a file lock around
the first creation; C, the hook skips a store that does not exist yet (which narrows, not removes, the hook's side
of the race). Its acceptance asks for a deterministic injected-error test, the two-process stress test marked
`slow`, and a consistency check (one collection; a write by one process read by the other).
