# Origin note: the third review of #84 (2026-11-03)

The review of the uncommitted revision over `1499944`, as pasted by the owner on 2026-11-03. Its view of the
scope decisions: US2's explicit per-record adoption is the correct safe default; treating a manifestless wiki as
its path is coherent but weakens #80, to be confirmed only with the documented rule that movable or multi-wiki
setups need manifests. Its findings:

1. [P1] `adopt_pages` is not bound to the records the owner reviewed: use `{path, ref_id}` entries, adopt only
   if the current sole candidate matches exactly, else `candidate changed`.
2. [P1] Duplicate handling can be bypassed by the early return: detect duplicate owned candidates in the
   importer before `_previous` or the early return, and define how `retain` reports multiple refs.
3. [P2] A legacy record can block a page that already has an owned record: resolve owned candidates first,
   consult legacy only when none exists; add an owned-plus-legacy test.
4. [P2] Ledger migration is not restart-complete: a crash after the rename and before retagging must read as
   "migration already completed; continue retagging", with deterministic lock ordering and a test.
5. [P3] The library class is `WikiImporter`, not `WikiSync`.

The spec answers them in S2, S3, S4, S6, FR-003a, FR-004, FR-007 and SC-2, SC-3; US1 states the manifest rule.
