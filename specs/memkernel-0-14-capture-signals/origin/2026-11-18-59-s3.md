## #59 issue body (2026-11-18, verbatim)

Research on 2026-10-27 (five independent research passes plus a synthesis, kept outside the repository) looked at where coding harnesses lose context, how memkernel rescues it today, and five context-rot effects. This issue records the findings and the proposed plan. Nothing here changes the frozen 0.5 code (`641a508`); the work starts after `v0.5.0`.

## 1. Defects in memkernel's own hooks

Code references are at the freeze commit `641a508`. Each defect was found independently by at least two passes.

| # | Defect | Where |
|---|---|---|
| D1 | **PreCompact stores a placeholder checkpoint that hides the real one.** The hook reads `event["summary"]`, which Claude Code's PreCompact payload doesn't carry (it has `trigger` and `custom_instructions`), so every compaction retains the "no summary" placeholder. Recovery takes the newest checkpoint by timestamp, so the placeholder hides any checkpoint the agent saved itself. Reproduced. | `templates/hooks/pre-compact.py:80`; `src/memkernel/lifecycle.py:113-121, 173-179` |
| D2 | **PostCompact output never reaches the model.** Claude Code injects hook stdout only for UserPromptSubmit, UserPromptExpansion, SessionStart and PostModelSwitch. What actually re-injects after compaction is SessionStart with `source=compact`. README.md:121 says otherwise. | `templates/hooks/post-compact.py`; `README.md:121` |
| D3 | **Claude's own compaction summary is discarded.** It arrives in PostCompact as `compact_summary`; no hook reads it. | `templates/hooks/post-compact.py` |
| D4 | **SessionStart ignores `source`.** The same block, plus a full `consolidate(revalidate=True)`, runs on every startup, resume, clear and compact: five times per `lc-compact` session in calibration. Likely cause of the memkernel arm's ~40% higher median session latency. | `templates/hooks/session-start.py`; `lifecycle.py:76-111` |
| D5 | Injected context lines carry no `ref_id`, yet the footer tells the agent to `get(ref_id)`. | `lifecycle.py:182-183` |
| D6 | No absolute relevance floor: min-max rescoring makes the top hit always 1.0, so six items are always injected; fixed generic queries; `touch=True` reinforces the same items. | `retrieval/search.py:161-166`; `lifecycle.py:80-82, 125-127` |
| D7 | Checkpoint and needs-review blocks have no size limit (Claude Code caps hook output at 10,000 characters). | `lifecycle.py:87, 93, 186-194` |
| D8 | Several paths put the same fact into context twice: template recalls repeat the hook, promotion keeps the source live, wiki import doesn't supersede its source, dedup is exact-hash only. | `templates/claude-memory-instructions.md`; `core/services.py`; `wiki/sync.py` |
| D9 | No SessionEnd hook; `on_session_end` is never called. | `templates/hooks/` |

**Effect on the 0.5 measured run:** its memkernel arm runs `templates/hooks/*` (`eval/lifecycle-suite/runner.py`), so its `lc-compact` results include D1–D4. The 0.5 report discloses this.

## 2. The five context-rot effects

| Effect | Evidence | What addresses it |
|---|---|---|
| Lost in the Middle | Strong for 2023 models; in current ones it shifts toward "distance from the end" past ~50% fill | Re-surface memory near the end (just-in-time recall, SessionStart(compact) re-injection); most actionable item first, one-line next step last |
| Attention Dilution | Strong and replicated (RULER, NoLiMa, Chroma's context-rot study) | Token budgets instead of item counts; gist + `ref_id` pointers with fetch on demand; a small wiki index read first |
| Distractor Amplification | Strong; semantically similar distractors hurt most | An absolute relevance floor with abstention; collapse near-duplicates and superseded versions at injection |
| Repetition Bias | Moderate | Event-aware hooks (nothing on resume); a per-session "already in context" ledger; one home per fact: CLAUDE.md for rules, the wiki for narrative, memory for atomic facts |
| Cost and Latency | Calibration: prompt-cache writes are 11% of tokens but ~54% of cost; memkernel adds +3.6% tokens but +40% latency | Cache-stable placement (volatile lines last); lighter hooks (revalidate and health on startup only); measure hook time and injected tokens |

## 3. Proposed plan

**Phase 0, now (outside the freeze)**
- Disclose D1–D4 in `report-0.5.0.md`.
- code-copilot-team (separate repository): installed hooks exit 0 silently when memkernel isn't importable; hook timeouts are set to 30000 in a field Claude Code reads as seconds (~8.3 h); installed copies have drifted from the templates; verify where the MCP server is registered.

**Phase 1, memkernel 0.5.1 (after the tag): hook correctness**
- SessionStart branches on `source`: full block on startup/clear, a compact recovery block on compact, nothing on resume.
- PostCompact retains `compact_summary` as the checkpoint, tagged with the Claude session id; PreCompact stops writing placeholders. On compact, inject a pointer to the checkpoint, not its text, so the summary isn't in context twice (acceptance test).
- `ref_id` on context lines; per-section token budgets; capped needs-review; bookkeeping out of the end slot; template de-duplication; revalidate/health only on startup.
- A SessionEnd hook that writes a spool marker only (SessionEnd has a 1.5 s budget).
- Correct README.md:121.

**Phase 2, memkernel 0.6: capture and anti-rot retrieval**
- A harness-neutral `BoundaryEvent` with `capture()` / `recover()`, keeping the `on_*` methods as wrappers; a `TranscriptReaderPort` with per-harness adapters; a cursor plus a detached worker, drained at the next SessionStart.
- Deterministic signal extraction (owner answers, owner turns, failed-then-fixed commands, PRs, commits, files changed), keyed by (session, record uuid, extractor version); secret redaction; `origin:` tags on every record; short-term storage with caps.
- Prompt-injection rules as requirements: free text only from owner turns and structured fields; tool and web text quoted, never re-injected verbatim; nothing of tool or web origin promoted automatically.
- An absolute relevance floor with abstention; task-specific just-in-time recall; supersede suggestions at retain; canonical hashing; recall collapses promoted and imported chains.

**Phase 3, wiki-studio and the memkernel bridge** (with gosha70/wiki-studio#38)
- Redacted session excerpts as citable sources in `knowledge/raw/`; page and index size lint; index entries with one-line descriptions; approval before session-derived pages become knowledge, with auto-approve off for transcript-origin pages.
- memkernel imports approved pages only (see #48).

**Phase 4, evidence**
- New lifecycle-suite tasks and a `memkernel_fixed` arm, measuring the rescue and each of the five effects, in a new measured run with its own calibration and preregistration.
