# Origin: Revalidate decisions that cite files: flag them, don't hide them

Source: https://github.com/gosha70/memkernel/issues/123 (copied 2026-11-13, verbatim)

## Issue body

## Why
#57's replay ([#121](https://github.com/gosha70/memkernel/pull/121); results in [`eval/decisions-57/results-k5.json`](https://github.com/gosha70/memkernel/blob/main/eval/decisions-57/results-k5.json) and [`results-k3.json`](https://github.com/gosha70/memkernel/blob/main/eval/decisions-57/results-k3.json), discussion in the [research note](https://github.com/gosha70/memkernel/blob/main/docs/research/implementation-decisions-57.md), sections 4–5) found two things:
- **Decisions are never revalidated.** `revalidate` checks `code` memories only. A probe retained a `decision` and a `code` memory citing the same file, then rewrote and deleted the file: the `code` memory was flagged both times, the `decision` neither time (`file_probe` in the results).
- **A file-hash check would catch real stale decisions, and also valid ones.** In code-copilot-team's history at `00d49c0`, the first cited file of both stale decisions changed after the decision date. So did the cited file of 3 of the 10 decisions still in force, two of them safety rules (`cited_file_history` in the results). `recall` hides flagged memories by default, so hiding flagged decisions would lose those rules.

## Proposed (needs a spec first)
- **Record a hash at retain.** A `decision` whose `source` names a file under the project root stores that file's hash, as `code` memories do. Only `source` is tracked for now, not the other paths in `evidence`.
- **Flag on change or loss.** `revalidate` flags such a decision when the file is missing or its hash changed, and clears the flag when the hash matches again or the decision is superseded.
- **Flagged code stays hidden; flagged decisions are returned.** `recall` keeps hiding flagged `code` memories, as today, but returns flagged decisions, so the agent re-checks the evidence instead of losing the decision.
- **The mark is an additive field.** Each `recall` result gains `needs_review` and `review_reason` (false and empty when not flagged). The preview is unchanged, and existing fields keep their meaning.
- **Older decisions** (no stored hash) are flagged only when the cited file is missing.
- No new record type or MCP tool; reuse the `code` revalidation path.

## Acceptance (sketch)
- The #57 file probe: the decision is flagged on rewrite and on delete, and `recall` still returns it with `needs_review: true` and a `review_reason`.
- The replay: every seed record is still found; decisions whose cited files changed come back flagged, not hidden.
- `recall` still hides flagged `code` memories.
- Stores from 0.1.x to 0.9.x load unchanged (the new key loads with a default).
