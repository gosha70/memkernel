# Origin: Anti-rot injection (#59 Phase 2, S1)

Source: https://github.com/gosha70/memkernel/issues/128 (copied 2026-11-15, verbatim)

## Issue body

## Why
#59 Phase 2 lists two anti-rot measures that Phase 1 (memkernel-0-7-hooks) deliberately left out: an absolute relevance floor with abstention ("calibrated later on the hooks' real queries") and collapsing duplicate chains at injection. Without them, a hook block fills its budget even when nothing in the store is about the task (attention dilution), and a fact can appear twice: once as a short-term source and once as the long-term memory promoted or imported from it (distractor amplification, repetition bias).

## Checked facts (`main` at `baff4dd`)
- **The final recall score cannot carry an absolute threshold.** `rescore()` min-max normalises the fused RRF score (`retrieval/search.py`, `rescore`), so the top result, or a lone result, always gets relevance 1.0. RRF itself is rank-based. The absolute signals available before normalisation are the dense cosine similarity (`1 − distance`, `storage/chroma.py`, `search_dense`) and the raw BM25 score.
- **The hook blocks choose memories two ways.**
  - Normal startup (`startup`, `clear`) uses `_startup_context()`: `list_memories` ranked by type, importance and recency, with no query, so a query-based floor does not apply there.
  - Compact recovery with a checkpoint (`_compact_recovery`, the checkpoint text as the query) and `on_post_compact()` (a fixed generic query) call `recall()`.
- **Promoted chains are collapsed on two of the three paths.** `_distinct()` (`lifecycle.py`) drops a promoted memory's live `promoted_from` source on normal startup and in compact recovery; `on_post_compact()` renders its `recall()` results without it, so a promoted memory and its source can both appear there.
- **Wiki corrections are already hidden.** An approved page's `corrects:` supersedes the runtime memories it names (`wiki/sync.py`, `supersede()`), so `recall` and `list_memories` leave them out.
- **An exported memory and the page imported from it cannot be linked today.** The export writes `memkernel_ref` into the page's frontmatter, but the import's `retain` does not keep it on the imported memory, so collapsing that pair needs new provenance metadata.

## Proposed (for a spec)
1. **An absolute floor on the recall paths, from a pre-normalisation signal.** A memory enters a hook block from `recall()` only when its dense cosine similarity (or a stated combination with raw BM25) to the block's query is at or above a floor, calibrated on the hooks' real queries; when nothing passes, the block says so (abstention) instead of filling its budget. The normal startup path has no query and keeps its ranking.
2. **Consistent promoted-chain collapse.** `on_post_compact()` applies the same collapse as the other two paths, so a promoted memory and its source never both appear in any hook block.
3. **Imported-page collapse: deferred** (decision for the spec). Collapsing an exported memory with the page imported from it needs the import to keep `memkernel_ref` as provenance metadata, a new key; S1 does not add it unless the spec decides to.
4. **Measurement.** The #57 corpus and its later-task queries go through the new hook selector (not MCP `recall`), counting retained hits and abstentions per case at the calibrated floor; injected tokens per block before and after. The ordinary #57 replay runs only as a regression check that MCP `recall` is unchanged.

## Out of scope
- Changing `recall`'s results for MCP callers (the floor and the collapse are for the hook blocks only, unless the spec decides otherwise).
- Near-duplicate merging, supersede suggestions and canonical hashing (S3).
- Transcript capture (S2).

## Acceptance (sketch)
- A compact-recovery or post-compact block with no memory above the floor shows an abstention line, not filler.
- A promoted memory and its source never both appear in one block, on any of the three paths (`on_post_compact()` included).
- Through the hook selector, the #57 corpus reports retained hits and abstentions per case at the calibrated floor.
- The ordinary #57 replay (MCP `recall`) is unchanged: same rankings as `results-k5.json`.
- The floor value and its calibration data are in the spec.
