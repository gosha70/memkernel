# Origin note: Track B amended to option B (2026-10-16)

Decision by the repository owner on 2026-10-16, in the session that ran task 11:

> approve B

What was decided. Track B's evidence for issue #17 comes from a
**maintainer-run supplemental evaluation** of the four lifecycle claims
(retain across sessions, revalidation after a repository change, sharing
through the wiki bridge, recovery across compaction), run by a minimal runner
in this repository. Entering memkernel as a retrieval arm of
`agent-memory-bench` continues in parallel and is not a 0.5.0 release gate.

Why the constraint changed. The second review round of 2026-10-15 added
"no benchmark runner, judge, event schema or statistics code of our own" on
the premise that the public harness covers the lifecycle claims. Task 11
(`research/2026-10-15-task11-agent-memory-bench.md`, sections 5 and 10)
refuted that premise on `c1b15726`: sequence mode carries only the memory
store between sessions, so the files-only controls carry nothing; there is
no second-namespace session, no compaction control, and memkernel's hooks
cannot run in the participant image; the retrieval grid itself needs a relay
absent from that commit, harness edits to register an arm, HTTP hosting
behind the broker, and an untested Claude route. The constraint is therefore
**narrowed to the retrieval grid**: memkernel writes no grid runner, no judge
and no statistics engine, and writes only the orchestration the four
lifecycle scenarios need.

Limits accepted with the decision (reviewer, 2026-10-16): bounded
orchestration; frozen per-arm persistence rules with identical first-session
information and save opportunity; calibration separate from measurement and
excluded from results, with live compaction proven during calibration; a
credential-free demonstration with simulated events before any paid session;
results labelled as maintainer-run and kept separate from any upstream
retrieval results, failures and nulls included.

Unchanged: the origin claim in `plan.md`, the positioning, Track A, the
preregistration and freeze rules, no LLM judge, no token-savings claim.
