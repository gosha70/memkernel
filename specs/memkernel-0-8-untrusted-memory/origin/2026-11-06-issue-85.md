From gosha70/memkernel#85 ("Injected memory is untrusted text: present it as data, and ship a recommended Claude
Code permissions example"):
- Why: the `SessionStart` hook injects stored memory (the latest checkpoint verbatim, and context lines) into the
  model's context, with nothing marking it as quoted data; that text can come from tool output, web pages, clipped
  sources or wiki pages.
- Proposed: (1) mark injected memory as data, a clearly delimited block with one line saying the contents are stored
  notes, not instructions, keeping the headings and the 9,000-character budget; (2) a recommended permissions
  example in `templates/` with README text: deny writes to `.memkernel/**`, deny edits to the hook scripts and
  `.claude/settings.json`, and a note on "always allow" prompts mid-session; (3) optional: a lint or health finding
  for stored memories that look like instructions.
- Acceptance (sketch): the startup and compact blocks present stored text inside a marked data block, pinned by a
  test; the example settings file is valid JSON for Claude Code's `permissions` schema, current at the time; the
  README links it; no change to MCP tools or ports.

Facts checked on 2026-11-06 against Claude Code's documentation (code.claude.com/docs/en/permissions and
/settings):
- `Edit(path)` rules apply to every built-in tool that edits files; `Write(path)` rules are accepted but never
  match, so `Edit` is the rule to write. Read and Edit deny rules also cover file commands Claude Code recognises
  in Bash (`cat`, `sed`, `tee`, ...) and redirections, not a program that writes files without naming them.
- A `/path` rule in `.claude/settings.json` anchors at the project's primary working directory; patterns use
  gitignore syntax.
- A deny rule can't be overridden by an allow rule; deny and ask rules in a committed `.claude/settings.json` apply
  at once, without the workspace-trust step that allow rules wait for.
- Settings files are strict JSON (no comments); `$schema` is `https://json.schemastore.org/claude-code-settings.json`.
- `.claude` and `.git` are protected paths: writes to them already prompt, except in `bypassPermissions` mode.
