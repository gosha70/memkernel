# Plan: compaction hooks that do what they say (#68)

## Payload facts, confirmed 2026-10-29
Checked against the Claude Code hooks reference, https://code.claude.com/docs/en/hooks (the page shows no
version or date); Claude Code 2.1.312 installed locally. The spec relies only on these:
- **PreCompact** input: the common fields (`session_id`, `transcript_path`, `cwd`, `hook_event_name`) plus
  `trigger` (`manual` or `auto`) and `custom_instructions` (what the user passed to `/compact`, else `null`). No
  summary field. Its output is not added to the model's context.
- **PostCompact** input: the common fields plus `trigger` and `compact_summary` ("the conversation summary
  generated by the compact operation"). "PostCompact hooks have no decision control"; its output is not added to
  context.
- **SessionStart** input: the common fields plus `source`: `startup`, `resume`, `clear`, `compact` ("Auto or
  manual compaction") or `fork`. "Claude Code adds a SessionStart hook's plain-text stdout to Claude's context."
  The reference does not say whether SessionStart(`compact`) runs before or after PostCompact.
- **Plain stdout reaches the model** only for `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart` and
  `PostModelSwitch`; for other events it goes to the debug log.
- **Cap:** injected output is capped at 10,000 characters (larger output is saved to a file and replaced by a
  2,000-character preview).

## Approach
- `MemoryLifecycle` gains `on_session_start(source=...)` and `capture_compact_summary(...)`; `on_pre_compact`
  stops writing a placeholder. The existing methods keep their names and, for library callers that pass no
  `source`, their output.
- The three hook scripts read their stdin JSON and pass the confirmed fields through; they still exit 0.
- The `compact` recovery block never repeats Claude Code's own summary, whichever of the two hooks runs first:
  checkpoints captured from `compact_summary` are tagged and left out of that block (FR-004).

## Files
